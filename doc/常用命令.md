# BMC AutoInsight 常用命令说明

本文档描述 **BMC AutoInsight**（企业版）的命令行用法。程序入口为项目根目录下的 `main.py`，通过 `python main.py <子命令>` 调用。

---

## 项目介绍

**BMC AutoInsight** 是一套基于 **Redfish** 的 BMC 带外巡检与自动化工具，主要能力包括：

| 能力 | 说明 |
|------|------|
| 单目标巡检 | 采集系统、温度、风扇、功耗、存储、事件日志等，生成 JSON / HTML / TXT / Excel 报告 |
| 规则告警 | 按阈值检测温度、风扇、内存、磁盘等并输出告警项 |
| 硬件与固件信息 | 汇总型号、序列号、BIOS、BMC 固件、CPU、内存、硬盘、主板等信息 |
| API 冒烟测试 | 自动发现可 GET 的 OData 路径并执行连通性检查（期望 HTTP 200） |
| 远程电源 | 查询或控制主机上下电、重启（含安全确认与 dry-run） |
| Mock 演示 | 无需真实 BMC，使用本地夹具跑通流程与报告导出 |
| 批量巡检 | 通过 CSV 对多台 BMC 依次采集并汇总报告 |

**使用前准备**：安装依赖 `pip install -r requirements.txt`，并配置 `config/config.ini` 或 `config/config.yaml`（主机、账号、密码、SSL 等）。可选参考 `config/config.ini.example`。

**报告输出目录**：默认在项目 `reports/` 下，文件名通常带时间戳。

---

## 基础巡检：`inspect`

### 功能

连接配置的 BMC，执行一次完整 Redfish 巡检：系统信息、热管理、电源模块、存储（可能因权限跳过）、事件日志探查等；应用传感器展示规则后，执行 API 冒烟测试，并将**巡检数据、硬件摘要、API 冒烟结果**写入报告（默认四种格式全导出）。

### 示例

```bash
# 使用当前配置连接 BMC 并巡检
python main.py inspect

# 指定导出格式（逗号分隔）
python main.py inspect --exports json,html,txt,xlsx
```

### 说明

- 需能成功登录 BMC（Session 或 Basic，见配置中的 `auth_mode`）。
- `--exports` 默认为 `json,html,txt,xlsx`；若未安装 `openpyxl`，Excel 可能提示跳过。
- `PowerState=Off` 时，无读数的传感器在报告中显示「【服务器关机，传感器无数据】」；开机状态下无读数显示「【该传感器未上报数据】」。

## 电源控制

### `power-status`

#### 功能

只读查询当前系统 **PowerState** 及关联摘要信息（如型号、健康状态、资源 URI），不向 BMC 下发电源变更。

#### 示例

```bash
python main.py power-status
```

#### 说明

无需 `--confirm`；适合运维前快速确认主机是否上电。

---

### `power-on`

#### 功能

向 BMC 请求**远程开机**（Redfish 语义一般为 `ResetType=On`）。默认受 `power.dry_run` 与确认参数保护，防止误操作。

#### 示例

```bash
# 默认可能为 dry_run（仅模拟，不真实下发，依配置而定）
python main.py power-on --confirm

# 真实向 BMC 下发开机（须同时带 --confirm 与 --execute）
python main.py power-on --confirm --execute
```

#### 说明

- **未带 `--confirm`** 的电源变更命令会被拒绝执行。
- **`--execute`** 用于在配置为 `dry_run=true` 时仍执行真实 Redfish 调用；危险操作请谨慎使用。
- 也可在配置中将 `power.dry_run` 设为 `false` 再配合 `--confirm` 使用（具体以项目文档与 `config` 为准）。

---

### `power-off`

#### 功能

向 BMC 请求**远程强制关机**（危险的带外操作），通常对应 `ResetType=ForceOff`。

#### 示例

```bash
python main.py power-off --confirm
python main.py power-off --confirm --execute
```

#### 说明

- 与 `power-on` 相同：**必须 `--confirm`**；真实下发常需 **`--execute`** 或关闭 dry_run。
- 可能导致业务中断，请在变更窗口执行。

---

### `power-restart`

#### 功能

向 BMC 请求**远程强制重启**，通常对应 `ResetType=ForceRestart`。

#### 示例

```bash
python main.py power-restart --confirm
python main.py power-restart --confirm --execute
```

#### 说明

- 同样需要 **`--confirm`**；真实下发配合 **`--execute`** 或配置中的 dry_run 策略。
- 属于高危操作，请确认无关键业务受影响。

---

## 硬件信息查询：`hardware-info`

### 功能

通过 Redfish 汇总**服务器型号、序列号、制造商、BIOS 版本、BMC 固件版本、CPU、内存、硬盘、主板**等信息；可同时执行附带 **API 冒烟**（可调路径数量），并将结果导出为报告。

### 示例

```bash
python main.py hardware-info

# 附带 API 冒烟最多发现的路径数（默认 50）
python main.py hardware-info --max-paths 30

# 指定导出格式
python main.py hardware-info --exports json,html,xlsx

# 使用本地 Mock，不连接真实 BMC（--mock 须写在子命令前）
python main.py --mock hardware-info
```

### 说明

- 存储、Processors、Memory、Drives 等依赖 BMC 开放的 Redfish 资源；权限不足时部分字段可能为空，报告中会有相应说明。
- 命令退出码：若附带 API 冒烟存在失败用例可能返回非 0（与 `api-test` 行为一致）。
- **注意**：全局参数 **`--mock` 必须在子命令之前**，例如 `python main.py --mock demo`，否则不会生效。

## API 冒烟测试：`api-test`

### 功能

自动从 Service Root 起按 `@odata.id`（及受限的 Actions 引用）发现并排队 **GET** 请求，校验**连通性与 HTTP 状态码是否为 200**；合并 `api_test/cases/smoke.yaml` 中的手工用例；在控制台打印用例名称、路径、状态、耗时、是否通过，并导出独立 JSON/HTML 报告，同时可选生成汇总 HTML/Excel。

### 示例

```bash
python main.py api-test

# 限制自动 discovery 的路径数量上限
python main.py api-test --max-paths 40

python main.py --mock api-test
```

### 说明

- 默认使用配置文件中的 BMC 凭证；冒烟失败（非 200 或异常）时进程退出码为 **1**。
- 部分 BMC 会对特定 URI 返回 403，该路径可能被判为失败，属预期现象，可按需在 `api_test/discovery.py` 中扩展跳过规则或在 YAML 中调整期望。
- 与 `inspect` / `hardware-info` 等不同，本子命令聚焦于**接口层面**的快速连通性验证。

## 帮助：`--help`

### 功能

输出 argparse 生成的程序说明：全局选项（如 `--mock`）、子命令列表与各子命令参数说明；电源相关还会在 epilog 中给出简要安全提示示例。

### 示例

```bash
# 主帮助（子命令列表）
python main.py --help

# 某一子命令的帮助
python main.py inspect --help
python main.py power-on --help
python main.py api-test --help
python main.py hardware-info --help
```

### 说明

- 程序在代码中注册名为 `bmc-autoinsight` 的 argparse prog，实际运行仍以 `python main.py` 为准。
- 不确定参数时，优先使用 `<子命令> --help`。

## 增补：`hardware-info`

### 功能

查询服务器硬件信息、**BIOS 版本**、**BMC 固件版本**、**CPU**、**内存**、**硬盘**（以及与 Redfish 开放程度相关的型号、序列号、制造商、主板等综合信息）。

### 示例

```bash
python main.py hardware-info

# 附带 API 冒烟最多发现的路径数（默认 50）
python main.py hardware-info --max-paths 30

# 指定导出格式
python main.py hardware-info --exports json,html,txt,xlsx

python main.py --mock hardware-info
```

### 说明

- 与同页前文 **「硬件信息查询：`hardware-info`」** 章节互补；该行文为命令要点摘要，细则（权限、退出码、`--mock` 位置）以前文为准。
- 依赖 BMC 开放的 Processors/Memory/Storage 等 URI；无权访问时字段可能为空，报告中含说明。

## 报告清理：`clean-reports`

### 功能

扫描项目 **`reports/`** 目录下、文件名符合 **`名称_YYYYMMDD_HHMMSS.扩展名`** 的导出文件，将**同一时间戳前缀（stem）的一组文件**视为同一批报告（如一次导出的 `.html`/`.json`/`.xlsx`/`.txt`），按组最新修改时间排序，**仅保留最近的若干组**，删除更早的全部文件；**.py** 等源码文件不参与清理。

### 示例

```bash
# 默认保留最近 5 组导出
python main.py clean-reports

# 仅保留最近 3 组
python main.py clean-reports --keep 3

# 只打印将要删除/保留的路径，不真实删除磁盘文件
python main.py clean-reports --dry-run

python main.py clean-reports --help
```

### 说明

- **不连接 BMC**，仅本地文件操作。
- **`--keep N`**：`N ≥ 1`，表示保留最近的 **N 批**导出（每组可含多个后缀文件）。
- 文件名**不符合**上述时间戳 stem 格式的文件：**一律保留**，避免误删人工放入的报告或其它文件。
- 不确定行为时请以 `python main.py clean-reports --help` 为准。
